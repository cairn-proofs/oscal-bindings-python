OSCAL Python data bindings — top-level re-export of oscal_bindings.v1.

The implementation lives in the major-version package oscal_bindings.v1. This module defines no symbols of its own: it re-exports that package's public surface so callers can use the shorter oscal_bindings path, and it star-imports oscal_bindings.v1.models so every generated model name is importable directly from oscal_bindings.

Because these are re-exports rather than wrappers, a name reached through this module is the same object as the one reached through oscal_bindings.v1, so isinstance agrees regardless of which path a class came from.

__all__ is taken from oscal_bindings.v1.__all__ rather than restated, so the two surfaces cannot drift apart.

>>> from oscal_bindings.v1 import parse_oscal_file, serialize_oscal

>>> from oscal_bindings import parse_oscal_file, serialize_oscal

class OscalDateTime(datetime.datetime): 
 45class OscalDateTime(datetime):
 46    """A ``datetime`` with a timezone that keeps every fraction digit of its text.
 47
 48    ``datetime`` stores microseconds only. A value that was parsed from
 49    ``2024-01-02T03:04:05.1234567Z`` has ``microsecond == 123456`` and keeps
 50    the full digits in `fraction`. `isoformat`, `to_string`, and the JSON
 51    serialization of a model write them again. A value that is constructed in
 52    Python, with no `fraction`, writes its microseconds as a ``datetime`` does.
 53
 54    **Equality and order.** Two values are equal when they name the same
 55    instant, with every digit counted: ``.1234567`` and ``.1234568`` differ, and
 56    ``.120`` and ``.12`` are equal. The same holds in a comparison with a plain
 57    ``datetime``, which counts as having no digits beyond the microsecond. The
 58    hash agrees with equality.
 59
 60    **Arithmetic and precision.** Only the standard library's microsecond
 61    methods are limited to microseconds:
 62
 63    - ``value + timedelta`` and ``value - timedelta`` keep the digits beyond the
 64      sixth, because a ``timedelta`` has no finer part to change them.
 65    - ``replace`` and ``astimezone`` keep the digits, unless ``replace`` sets
 66      ``microsecond``.
 67    - ``value - other`` gives a ``timedelta``, which holds microseconds. The
 68      digits beyond the sixth of both operands are **not** in the difference, so
 69      the difference of two values that differ only after the sixth digit is
 70      zero, while ``value == other`` is false. Compare values with ``<``, ``==``
 71      and ``>``, not by a difference, when digits beyond the sixth matter.
 72    - ``timestamp()``, ``strftime()``, ``timetuple()``, ``time()``,
 73      ``timetz()``, and ``isoformat(timespec=...)`` with a ``timespec`` other
 74      than ``"auto"`` use the microsecond value only and drop the digits beyond
 75      the sixth.
 76    - ``fromisoformat`` keeps the digits of the text. ``combine``,
 77      ``fromtimestamp``, ``now``, and the other constructors have no text to
 78      keep them from.
 79
 80    A value is immutable and can be pickled and copied.
 81    """

102
103        ``fraction`` is the text after the decimal point of the seconds, with at
104        least the digits of ``microsecond`` as its first six (padded with
105        zeros). It is empty for a whole second. Omit it to write the
106        microseconds as ``datetime`` does.

192        """Parse an ISO 8601 text and keep every digit after the decimal point.
193

195        it may have more than six fraction digits.

203            + digits[:_MICRO_DIGITS]

A datetime with a timezone that keeps every fraction digit of its text.

datetime stores microseconds only. A value that was parsed from 2024-01-02T03:04:05.1234567Z has microsecond == 123456 and keeps the full digits in fraction. isoformat, to_string, and the JSON serialization of a model write them again. A value that is constructed in Python, with no fraction, writes its microseconds as a datetime does.

Equality and order. Two values are equal when they name the same instant, with every digit counted: .1234567 and .1234568 differ, and .120 and .12 are equal. The same holds in a comparison with a plain datetime, which counts as having no digits beyond the microsecond. The hash agrees with equality.

Arithmetic and precision. Only the standard library's microsecond methods are limited to microseconds:

  • value + timedelta and value - timedelta keep the digits beyond the sixth, because a timedelta has no finer part to change them.
  • replace and astimezone keep the digits, unless replace sets microsecond.
  • value - other gives a timedelta, which holds microseconds. The digits beyond the sixth of both operands are not in the difference, so the difference of two values that differ only after the sixth digit is zero, while value == other is false. Compare values with <, == and >, not by a difference, when digits beyond the sixth matter.
  • timestamp(), strftime(), timetuple(), time(), timetz(), and isoformat(timespec=...) with a timespec other than "auto" use the microsecond value only and drop the digits beyond the sixth.
  • fromisoformat keeps the digits of the text. combine, fromtimestamp, now, and the other constructors have no text to keep them from.

A value is immutable and can be pickled and copied.
