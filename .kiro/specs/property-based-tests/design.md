# Design Document

## Overview

This feature adds a property-based test suite (the **PBT_Suite**) to `oscal-bindings` using [Hypothesis](https://hypothesis.readthedocs.io/). The suite exercises the public API — the parser functions, the `OscalDoc` facade, the back-matter builders, and `validate_element` — by asserting invariants that must hold across many inputs.

Inputs come from these sources:

1. **Real OSCAL documents** fetched from two commit-pinned remote corpora (NIST `oscal-content` and AWS `oscal-content-for-aws-services`). These seed the round-trip and facade properties.
2. **A local, opt-in corpus** read in place from the path in `OSCAL_BINDINGS_LOCAL_CORPUS` (Req 11). It exists because NIST publishes no mapping-collection example; when configured, its documents join the same corpus pool.
3. **Synthetic inputs** generated by Hypothesis strategies, used *only* for the back-matter builders and `validate_element` leaf types. No full synthetic OSCAL document is ever generated.

This is a **test-only feature**. The only change outside `tests/` is uncommenting one line in `pyproject.toml` to add Hypothesis as a test dependency. Nothing under `src/oscal_bindings/` is modified.

### Design Goals

- Reproducibility: corpus inputs are pinned by commit SHA, so the input set is stable over time.
- Speed and network hygiene: fetch each corpus document once, cache locally, reuse across runs and across parallel workers.
- Fail-loud semantics: an unreachable corpus is a test *failure*, never a silent skip.
- Zero new runtime dependencies: corpus fetching uses the Python standard library (`urllib`), not `requests`. The only added dependency is the test-only `hypothesis`.

> **Prerequisite (resolved):** The two corpus commit SHAs (`NIST_CORPUS.sha` and `AWS_CORPUS.sha`) are now pinned. Each is pinned to its repository's HEAD commit as of the pin date: NIST `oscal-content` → `78650f02ad9321bb7b817846f8fbd4f2bcd620de`, AWS `oscal-content-for-aws-services` → `4a1779ffb556c4ab8fb3dad94a19d4d198116803`. The input set is therefore fixed and reproducible.

> **Coverage gap (known limitation):** The pinned NIST commit (identical to upstream `main`) has example documents for only 7 of the 8 OSCAL types. No `mapping-collection` example exists on NIST `main`, `develop`, or `prototype-mapping-examples`, and the AWS corpus is component-definitions only. The remote corpora therefore cover 7 types (Req 2.4). Mapping-collection is covered only by the local opt-in corpus (Req 11). CI does not set `OSCAL_BINDINGS_LOCAL_CORPUS`, so **CI exercises 7 of 8 document types**; the mapping-collection coverage check reports a visible skip there. No existing test parses real mapping-collection JSON either (`tests/test_document.py` uses `model_construct()`).

### Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Fetch transport | stdlib `urllib.request` | Only `pydantic` is a runtime dep; adding `requests` for tests is unnecessary weight. `urllib` covers HTTPS GET of a tarball. |
| Fetch granularity | One **codeload tarball per pinned SHA**, extracted once | GitHub `codeload.github.com/{owner}/{repo}/tar.gz/{sha}` returns the whole tree in a single request. Grabbing dozens of example files per-file over `raw.githubusercontent.com` would mean dozens of requests and dozens of lock points. One tarball per corpus is simpler and more robust. |
| Cache location | `tests/.corpus_cache/` (git-ignored) | Lives with the tests, survives across runs, easy to `.gitignore`. |
| Concurrency safety | Atomic extract via temp dir + `os.replace`, guarded by a per-corpus file lock | Safe across `pytest-xdist` worker processes (separate interpreters, shared filesystem). `os.replace` is atomic on the same filesystem. |
| Hypothesis input for corpus properties | `data.draw(st.sampled_from(corpus_docs))` inside the test body (the `st.data()` pattern), where `corpus_docs` comes from a session fixture | `@given` strategies are evaluated at import/decoration time, so a fixture value cannot be referenced inside `@given(...)`. Taking the corpus list as a normal fixture argument and drawing from it via a `data` parameter defers the draw to run time. `sampled_from` still lets Hypothesis explore the fixed corpus (and shrink to a minimal failing doc) without synthesizing OSCAL. |
| Empty-partition handling | Fixtures assert each corpus partition is non-empty before use | `st.sampled_from([])` raises `InvalidArgument`. An empty partition (e.g. no AP/AR docs loaded) is treated as a hard failure, consistent with the Req 5 fail-loud philosophy — empty is a failure, not a skip. |
| Corpus loading | session-scoped pytest fixtures | Load and parse the corpus once per session, shared across all workers via the on-disk cache. |
| NIST document selection | Broad glob + top-level OSCAL root-key filter | A blanket `**/*.json` glob matches non-document JSON in the NIST repo (metaschema, config, etc.) that `parse_oscal` rejects, producing spurious round-trip failures. Filtering loaded JSON to those whose single top-level key is one of the 8 recognized OSCAL document roots is robust to repo layout changes and keeps only parseable documents. |
| Mapping-collection source | External, opt-in `OSCAL_BINDINGS_LOCAL_CORPUS` path, read in place; never vendored, cached, or copied | NIST publishes no mapping-collection example, and the only real one available is derived from a confidential source. The repo is public, and the sdist `only-include` ships the whole `tests/` directory, including untracked files that are not git-ignored, so any copy under the repo (even git-ignored under `tests/.corpus_cache/`, which a future packaging change could expose) risks publication. Reading from an external absolute path keeps the document off every artifact. Opt-in keeps CI and contributors unaffected. |
| Local corpus when unset | Empty list; only the mapping-collection coverage check skips, with a reason naming the env var | This is the one sanctioned skip. It is visible in pytest output so the 7-type CI limitation stays explicit. Req 5.4's no-skip rule for the remote corpora is unchanged. |
| Local corpus misconfigured | Set-but-missing/unreadable, or zero OSCAL docs after the root-key filter → `CorpusError` naming the env var | A developer who set the variable expects coverage; silently degrading to a skip would hide a typo. The message names the variable and never includes document content. |

## Architecture

### File Layout

New files, all under `tests/`:

```
tests/
  conftest.py                 # NEW — session-scoped corpus fixtures + Hypothesis profiles
  support/
    __init__.py               # NEW
    corpus.py                 # NEW — Corpus_Fetcher: pinning, fetch, cache, concurrency, hard-fail
  strategies.py               # NEW — Hypothesis strategies for builders + validate_element leaf types
  test_prop_roundtrip.py      # NEW — Req 6 round-trip properties (corpus-seeded)
  test_prop_facade.py         # NEW — Req 7 OscalDoc facade properties (corpus-seeded)
  test_prop_builders.py       # NEW — Req 8 builder schema-validity property
  test_prop_validate_element.py # NEW — Req 9 validate_element properties
  test_corpus_fetcher.py      # NEW — Req 2-5 fetcher unit/example tests (cache, concurrency, hard-fail)
  test_local_corpus.py        # NEW — Req 11 local opt-in loader example tests (tmp_path + monkeypatch)
  test_corpus_coverage.py     # NEW — Req 11.9/11.15 mapping-collection coverage check (the one sanctioned skip)
```

**Justification for the split.** The existing suite has one test module per source module (`test_parser.py`, `test_document.py`, ...). The PBT_Suite follows the same "one module per concern" convention but names property modules `test_prop_<family>.py` so they are visually distinct from the existing example-based modules and can be selected as a group (`pytest tests/test_prop_*.py`). The `Corpus_Fetcher` is test *infrastructure* rather than a property family, so it lives under `tests/support/` (importable, not collected as tests) with its own dedicated example-based test module `test_corpus_fetcher.py`. A shared `conftest.py` holds the session-scoped corpus fixtures and Hypothesis profile registration so every property module gets them for free.

### 2. `tests/support/corpus.py` — Corpus_Fetcher (Req 2-5)

Pins, fetches, caches, and exposes corpus documents.

```python
# Pinning (Req 2.1, 2.2) — pin to specific full 40-hex commit SHAs.
# NOTE: both `sha` values below are pinned to each corpus repo's HEAD commit
# as of the pin date, so the input set is stable and reproducible over time.
NIST_CORPUS = CorpusSpec(
    name="NIST oscal-content",
    owner="usnistgov",
    repo="oscal-content",
    sha="78650f02ad9321bb7b817846f8fbd4f2bcd620de",  # pinned to repo HEAD as of pinning
    include_globs=("**/*.json",),         # broad glob; narrowed by root-key filter below (Req 2.4)
    require_oscal_root=True,               # keep only JSON whose top-level key is an OSCAL root
)
AWS_CORPUS = CorpusSpec(
    name="AWS oscal-content-for-aws-services",
    owner="awslabs",
    repo="oscal-content-for-aws-services",
    sha="4a1779ffb556c4ab8fb3dad94a19d4d198116803",  # pinned to repo HEAD as of pinning
    include_globs=("component-definitions/**/*.json",),  # scope (Req 2.3)
    require_oscal_root=True,
)

# The 8 recognized OSCAL document root keys. A parseable OSCAL document is a
# JSON object with exactly one of these as its single top-level key.
OSCAL_ROOT_KEYS = frozenset({
    "catalog",
    "profile",
    "component-definition",
    "system-security-plan",
    "assessment-plan",
    "assessment-results",
    "plan-of-action-and-milestones",
    "mapping-collection",
})

CACHE_ROOT = Path(__file__).parent.parent / ".corpus_cache"   # tests/.corpus_cache (Req 3.3)


class CorpusError(RuntimeError):
    """Raised when a corpus cannot be fetched. Message includes corpus name + SHA."""


@dataclass(frozen=True)
class CorpusSpec:
    name: str
    owner: str
    repo: str
    sha: str
    include_globs: tuple[str, ...]
    require_oscal_root: bool = True   # drop JSON whose top-level key is not an OSCAL root

    @property
    def tarball_url(self) -> str:
        return f"https://codeload.github.com/{self.owner}/{self.repo}/tar.gz/{self.sha}"


@dataclass(frozen=True)
class CorpusDoc:
    """A single fetched corpus document."""
    corpus_name: str
    rel_path: str          # path within the repo tree — used as the doc identifier (Req 6.4)
    raw_bytes: bytes       # the document as bytes (drives str/bytes equivalence, Req 6.3)
    root_key: str          # the single top-level OSCAL key (in OSCAL_ROOT_KEYS);
                           # set by the root-key filter, drives AP/AR partitioning


def ensure_corpus(spec: CorpusSpec, *, cache_root: Path = CACHE_ROOT) -> Path:
    """Ensure the corpus tree for `spec.sha` is extracted under the cache.

    Cache-hit (Req 3.2): if the extracted marker dir exists, return it with no
    network. Cache-miss (Req 3.1): download the tarball at the pinned SHA,
    extract atomically, return the dir. Concurrency-safe (Req 4).
    """


def load_corpus_docs(spec: CorpusSpec, *, cache_root: Path = CACHE_ROOT) -> list[CorpusDoc]:
    """Return all documents in `spec` matching its include_globs, reading from cache.

    When `spec.require_oscal_root` is set, each candidate JSON file is parsed
    just far enough to inspect its top-level keys, and any file whose single
    top-level key is not in `OSCAL_ROOT_KEYS` is dropped. This filters out the
    non-document JSON (metaschema, config, etc.) that `**/*.json` would
    otherwise sweep in for the NIST corpus, so only parseable OSCAL documents
    are yielded as `CorpusDoc`s (Req 2.4).
    """


# Local opt-in corpus (Req 11). Holds an absolute path to one OSCAL JSON file
# or a directory of them. Unset in CI.
LOCAL_CORPUS_ENV = "OSCAL_BINDINGS_LOCAL_CORPUS"


def load_local_corpus_docs(*, environ: Mapping[str, str] = os.environ) -> list[CorpusDoc]:
    """Return documents from the local opt-in corpus, read in place.

    - Unset (or empty) env var → [] (Req 11.8).
    - File → that one file; rel_path = file basename (Req 11.1, 11.5).
    - Directory → every `**/*.json` under it; rel_path = path relative to the
      directory, POSIX-style (Req 11.2, 11.4). Absolute user paths never reach
      test IDs or diagnostics.
    - Each candidate goes through the same OSCAL root-key filter as the remote
      corpora; retained docs get corpus_name="local" and root_key set (Req 11.3).
    - No network, no Corpus_Cache writes, no copies (Req 11.6, 11.7).
    - Set but missing/unreadable, or zero docs after the filter → CorpusError
      whose message names LOCAL_CORPUS_ENV and never includes document
      content (Req 11.11-11.13).
    """
```

The root-key filter is factored into a small shared helper (e.g. `_oscal_root_key(raw: bytes) -> str | None`) used by both `load_corpus_docs` and `load_local_corpus_docs`, so the two sources cannot drift. Because a failing Hypothesis example prints the drawn `CorpusDoc`, `raw_bytes` is declared `field(repr=False)` so a local failure never dumps document content into terminal output; `corpus_name`, `rel_path`, and `root_key` remain in the repr for diagnostics (Req 6.4).

**Fetch + cache algorithm (Req 3, 4, 5):**

```
ensure_corpus(spec):
    target = cache_root / f"{spec.repo}-{spec.sha}"
    if target.is_dir() and (target / ".complete").exists():   # Req 3.2 cache hit
        return target
    lock = FileLock(cache_root / f"{spec.repo}-{spec.sha}.lock")   # cross-worker (Req 4.1)
    with lock:
        if target.is_dir() and (target / ".complete").exists():   # re-check under lock
            return target
        tmp = cache_root / f".tmp-{spec.repo}-{spec.sha}-{os.getpid()}"
        try:
            data = _http_get(spec.tarball_url)         # urllib GET (Req 3.1)
        except (URLError, HTTPError, TimeoutError) as e:
            raise CorpusError(                          # Req 5.1/5.2/5.3 — name + SHA
                f"Failed to fetch corpus '{spec.name}' at commit {spec.sha}: {e}"
            ) from e
        _extract_tar_gz(data, into=tmp)
        (tmp / ".complete").touch()
        os.replace(tmp, target)     # atomic publish — no partial dir observed (Req 4.2)
    return target
```

- **File lock** across xdist workers: a small `FileLock` helper using `os.open(..., O_CREAT | O_EXCL)` spin-with-backoff, or `fcntl.flock` on POSIX. The lock guarantees the download happens **at most once** (Req 4.1). Workers that lose the race re-check the `.complete` marker and return the cached tree.
- **Atomic publish**: extraction goes to a per-PID temp dir; `os.replace` swaps it into place in one atomic step, so no worker ever reads a half-extracted tree (Req 4.2). Because every worker ends up reading the same published tree, all observe identical content (Req 4.3).
- **Hard-fail**: any network/HTTP failure with no cached copy raises `CorpusError` whose message contains the corpus `name` and pinned `sha` (Req 5.1-5.3). The suite never calls `pytest.skip` for a missing corpus, so an unreachable corpus is a failure (Req 5.4).

### 3. `tests/conftest.py` — fixtures + Hypothesis profiles (Req 6, 7, 10)

```python
@pytest.fixture(scope="session")
def nist_docs() -> list[CorpusDoc]:
    return load_corpus_docs(NIST_CORPUS)     # loaded once per session

@pytest.fixture(scope="session")
def aws_docs() -> list[CorpusDoc]:
    return load_corpus_docs(AWS_CORPUS)

@pytest.fixture(scope="session")
def local_corpus_docs() -> list[CorpusDoc]:
    # [] when OSCAL_BINDINGS_LOCAL_CORPUS is unset; CorpusError when set but
    # invalid/empty, which errors every dependent test (Req 11.8, 11.11, 11.12)
    return load_local_corpus_docs()

@pytest.fixture(scope="session")
def all_corpus_docs(nist_docs, aws_docs, local_corpus_docs) -> list[CorpusDoc]:
    docs = [*nist_docs, *aws_docs, *local_corpus_docs]   # Req 11.14
    assert docs, "corpus is empty — cannot sample (fail-loud, Req 5.4)"
    return docs

# Convenience partitions for facade properties (Req 7.2/7.3). Each partition
# asserts non-emptiness so a downstream `st.sampled_from(...)` never receives
# an empty sequence (which raises InvalidArgument). An empty partition is a
# hard failure, consistent with the Req 5 fail-loud philosophy.
AP_AR_KEYS = {"assessment-plan", "assessment-results"}

@pytest.fixture(scope="session")
def ap_ar_docs(all_corpus_docs) -> list[CorpusDoc]:          # AP + AR only
    docs = [d for d in all_corpus_docs if d.root_key in AP_AR_KEYS]
    assert docs, "no Assessment Plan / Assessment Results documents in corpus"
    return docs

@pytest.fixture(scope="session")
def non_ap_ar_docs(all_corpus_docs) -> list[CorpusDoc]:      # the other 6 types (incl. local mapping-collection)
    docs = [d for d in all_corpus_docs if d.root_key not in AP_AR_KEYS]
    assert docs, "no non-AP/AR documents in corpus"
    return docs
```

Partitioning is by `root_key`, so a local mapping-collection document lands in
`non_ap_ar_docs` automatically and Property 6 exercises it. With the variable
unset, the partitions are exactly the remote-corpus partitions, which are
non-empty on their own.

The mapping-collection coverage check (`tests/test_corpus_coverage.py`) is the
one sanctioned skip (Req 11.9, 11.15):

```python
def test_mapping_collection_covered(all_corpus_docs):
    if not os.environ.get(LOCAL_CORPUS_ENV):
        pytest.skip(
            f"{LOCAL_CORPUS_ENV} is unset: no mapping-collection example is "
            "published by NIST, so this type is only covered locally"
        )
    assert any(d.root_key == "mapping-collection" for d in all_corpus_docs), (
        f"{LOCAL_CORPUS_ENV} is set but supplied no mapping-collection document"
    )
```

The skip reason appears in `pytest -rs` summaries and in Hatch's default
short-summary output. It is scoped to this one test; every other test runs
with the variable unset.

Each corpus property test takes the relevant partition fixture plus a
`data` parameter and draws the document inside the test body — the
`st.data()` pattern — because `@given` strategies are evaluated at
decoration time and cannot close over a fixture value:

```python
from hypothesis import given, strategies as st

@given(data=st.data())
def test_roundtrip_preserves_model(all_corpus_docs, data):
    doc = data.draw(st.sampled_from(all_corpus_docs))   # drawn at run time
    ...
```

Hypothesis profiles registered at import time:

```python
from hypothesis import settings, HealthCheck

settings.register_profile(
    "ci",
    max_examples=100,                       # >= 100 iterations per property
    deadline=None,                          # corpus parsing can be slow; no per-example deadline
    suppress_health_check=[HealthCheck.too_slow, HealthCheck.function_scoped_fixture],
    print_blob=True,                        # surface reproducible counterexamples (Req 10.4)
)
settings.register_profile("dev", max_examples=50)
settings.load_profile(os.environ.get("HYPOTHESIS_PROFILE", "ci"))
```

Corpus properties draw with `data.draw(st.sampled_from(...))` over a session-loaded list, so the network/parse cost is paid once even though Hypothesis draws many samples (Req 10.3 — no per-example fetching, no cache contention).

### 4. `tests/strategies.py` — synthetic strategies (Req 8, 9)

Strategies build **only** builder inputs and single leaf-type element dicts — never a full OSCAL document (Req 8.4, 9.4).

```python
# Builders (Req 8)
hex_digests = st.text(alphabet="0123456789abcdef", min_size=1, max_size=128)
algorithms  = st.sampled_from(list(Algorithm))          # enum members + their str values
hrefs       = st.from_regex(r"https?://[a-z0-9./-]{1,40}", fullmatch=True)
media_types = st.none() | st.sampled_from(["application/json", "text/xml", "application/pdf"])

def hash_strategy():   # -> kwargs for make_hash
def rlink_strategy():  # -> kwargs for make_rlink (respects media-type alias via kwarg media_type)
def resource_strategy():  # -> kwargs for make_resource (title/description/rlinks/uuid/document_ids)

# validate_element leaf types (Req 9)
#
# get_supported_element_types() returns the kebab-case name of EVERY BaseModel
# subclass in models.py (187 of them), including full document bodies (e.g.
# "catalog", "system-security-plan") and deeply-nested / recursive composite
# types. Generating instances of all of them would be a combinatorial blow-up
# (187 types x 100 examples) and would stall on recursive and heavily
# constrained models. Property 8 therefore exercises an explicit, documented
# allow-list of genuinely simple, flat, non-recursive leaf types.
#
# These kebab names are verified against get_supported_element_types() output.
# ("prop" is NOT a supported name — the model class is Property -> "property".)
LEAF_ELEMENT_TYPES: tuple[str, ...] = (
    "hash",          # Hash: {algorithm, value}
    "rlink",         # Rlink: {href, media-type?, hashes?}
    "link",          # Link: {href, rel?, media-type?, resource-fragment?, text?}
    "property",      # Property: {name, value, uuid?, ns?, class?, group?, remarks?}
    "document-id",   # DocumentId: {identifier, scheme?}
)

def leaf_instance_strategy(element_type: str) -> st.SearchStrategy[dict]:
    """Build a schema-valid dict for one allow-listed leaf `element_type` by
    constructing the mapped Pydantic model with generated field values and
    dumping by alias."""
```

The allow-list is a **deliberate, documented subset** chosen for flatness and
non-recursiveness — not the full `get_supported_element_types()` return.
Property 8 iterates `LEAF_ELEMENT_TYPES`; for each, the strategy produces a
minimal valid instance (required fields populated from Hypothesis, optionals
sometimes present), then `model_dump(by_alias=True, exclude_none=True)` to get
a validator-ready dict. `get_supported_element_types()` is still consulted at
run time to assert every allow-listed name is genuinely supported (Req 9.1).
Extending coverage to more (or all) supported types is a **bounded follow-on**.

## Data Flow

### Round-trip property (Req 6.1)

```
session fixture: ensure_corpus(NIST) + ensure_corpus(AWS)  [once, cache-backed]
    -> load_corpus_docs -> list[CorpusDoc]
    + load_local_corpus_docs()  [[] unless OSCAL_BINDINGS_LOCAL_CORPUS set; read in place]
    -> all_corpus_docs              (non-empty; asserted in fixture)
        -> @given(data=st.data())            # test also takes all_corpus_docs fixture
            doc = data.draw(st.sampled_from(all_corpus_docs))   # drawn in test body
            doc.raw_bytes --parse_oscal--> model_a
            model_a --serialize_oscal--> json_str
            json_str --parse_oscal--> model_b
            assert model_a == model_b        # Pydantic structural equality
```

### bytes/str equivalence (Req 6.3)

```
@given(data=st.data())                       # test also takes all_corpus_docs fixture
    doc = data.draw(st.sampled_from(all_corpus_docs))
    doc.raw_bytes --parse_oscal--> model_from_bytes
    doc.raw_bytes.decode("utf-8") --parse_oscal--> model_from_str
    assert model_from_bytes == model_from_str
```

### Structural mutation (Req 6.2)

Mutation is deliberately **conservative** to keep documents schema-valid. The
test draws a corpus document, parses it, and replaces a genuinely **optional
scalar** field — `metadata.remarks` (an `str | None` field, unlike `title`,
`version`, and `oscal-version`, which are all **required** in OSCAL metadata) —
with a Hypothesis-generated non-empty string. Because `remarks` lives on the
nested `metadata` block and Pydantic's `model_copy(update=...)` only replaces
**top-level** fields, the update is applied by **nested reconstruction**: copy
the metadata with the new field, then rebuild the body around the new metadata,
then rebuild the wrapper around the new body, e.g.

```
new_metadata = doc.body.metadata.model_copy(update={"remarks": drawn_text})
new_body     = doc.body.model_copy(update={"metadata": new_metadata})
new_wrapper  = doc.wrapper.model_copy(update={<body_attr>: new_body})
```

(a small `set_metadata_remarks(model, text)` helper encapsulates the upward
rebuild). The mutated wrapper is then re-serialized and run through the same
round-trip equality assertion. Because the mutation touches only an
already-optional scalar with a type-compatible value, the document stays valid.
Broader structural mutations (adding/removing array elements, nested objects)
are noted as a **bounded follow-on** and intentionally out of scope for the
first iteration to avoid generating invalid documents that would confuse
round-trip failures.

### Builder property (Req 8)

```
@given(hash_strategy() | rlink_strategy() | resource_strategy())   # per-builder param
    element = make_X(**kwargs)
    dumped  = element.model_dump(by_alias=True, exclude_none=True)
    revalidated = type(element).model_validate(dumped)
    assert revalidated == element     # produced element is schema-valid back-matter
```

### validate_element round-trip (Req 9.2)

```
supported = set(get_supported_element_types())            # Req 9.1
for element_type in LEAF_ELEMENT_TYPES:                    # allow-list, not the full 187
    assert element_type in supported                       # allow-list stays consistent
```

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system — essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

### Property 1: Round-trip preserves the model

*For any* corpus document, parsing it, serializing the result, and parsing that serialization again yields a model equal to the model from the first parse.

**Validates: Requirements 6.1, 11.14**

### Property 2: Mutated documents still round-trip

*For any* corpus document and *any* Hypothesis-generated non-empty string assigned to the optional `metadata.remarks` scalar (applied by nested reconstruction so the document stays schema-valid), the mutated document parses, serializes, and re-parses to an equal model.

**Validates: Requirements 6.2, 11.14**

### Property 3: `bytes` and `str` inputs parse identically

*For any* corpus document, parsing its UTF-8 `bytes` form and parsing its decoded `str` form produce equal models.

**Validates: Requirements 6.3, 11.14**

### Property 4: Facade accessors never raise on valid documents

*For any* corpus document wrapped in `OscalDoc`, accessing `metadata`, `uuid`, `oscal_version`, and `body` completes without raising.

**Validates: Requirements 7.1, 11.14**

### Property 5: `assessment_period()` succeeds for Assessment Plan / Assessment Results

*For any* Assessment Plan or Assessment Results corpus document, `assessment_period()` returns a `(start, end)` value without raising.

**Validates: Requirements 7.2**

### Property 6: `assessment_period()` rejects non-AP/AR documents

*For any* corpus document that is neither an Assessment Plan nor Assessment Results, invoking `assessment_period()` raises `OscalAccessError`.

**Validates: Requirements 7.3, 11.14**

### Property 7: Builders produce schema-valid back-matter

*For any* Hypothesis-generated inputs to `make_hash`, `make_rlink`, or `make_resource`, the produced element re-validates against its own model (i.e. is schema-valid back-matter content).

**Validates: Requirements 8.1, 8.2, 8.3**

### Property 8: `validate_element` round-trips allow-listed leaf types

*For any* element type in the documented `LEAF_ELEMENT_TYPES` allow-list (a deliberate subset of simple, flat, non-recursive types drawn from `get_supported_element_types()`) and *any* Hypothesis-generated instance of that type, `validate_element` reports it valid and the validated value round-trips back to an equivalent value. Covering the remaining supported types is a bounded follow-on.

**Validates: Requirements 9.1, 9.2**

### Property 9: `validate_element` rejects unknown element types

*For any* element type name absent from `get_supported_element_types()`, invoking `validate_element` with that name raises `OscalParseError`.

**Validates: Requirements 9.3**

## Testing Strategy

**Dual approach.** Property tests (above) cover input-varying invariants. Example/edge tests cover the Corpus_Fetcher infrastructure and configuration facts that do not vary meaningfully with input.

**Example / edge tests (in `test_corpus_fetcher.py`):**

- AWS corpus documents all live under `component-definitions/` (Req 2.3).
- NIST corpus root keys equal exactly the 7 published types, with `mapping-collection` absent (Req 2.4) — asserted after the root-key filter, which also confirms non-document JSON (metaschema/config) is dropped so it never reaches `parse_oscal`. An exact-set assertion means the test flags it if a future NIST pin adds a mapping-collection example, prompting a revisit of the local-corpus workaround.

**Local corpus example tests (in `test_local_corpus.py`, Req 11):** all use `tmp_path` fixture files and `monkeypatch.setenv`/`delenv`; none touch the real local document.

- Unset → `[]` (11.8).
- Single file → one doc, `corpus_name == "local"`, `rel_path` is the basename (11.1, 11.3, 11.5).
- Directory with nested OSCAL + non-OSCAL JSON → only OSCAL docs, `rel_path` relative to the dir (11.2, 11.3, 11.4).
- Set but missing path → `CorpusError` naming `OSCAL_BINDINGS_LOCAL_CORPUS` (11.11).
- Set, but no OSCAL docs after filter → `CorpusError` naming the variable, message excludes the file's content (11.12, 11.13).
- No `rel_path` is absolute or contains the configured root (11.4, 11.5).
- No network and no cache writes: `_http_get` monkeypatched to raise, `CACHE_ROOT` monkeypatched to an empty `tmp_path` subdir that stays empty (11.6, 11.7).

**Mapping-collection coverage check (in `test_corpus_coverage.py`):** skips with a reason naming the variable when unset; asserts ≥1 `mapping-collection` doc in `all_corpus_docs` when set (11.9, 11.15). With a real local document configured, Properties 1–4 and 6 also sample it through `all_corpus_docs` / `non_ap_ar_docs` (11.14).

**Known limitation:** CI does not set `OSCAL_BINDINGS_LOCAL_CORPUS`, so CI covers 7 of 8 document types and reports one skip. Mapping-collection coverage is local-only until NIST (or another public, pinnable source) publishes an example.
- Cache-miss downloads and stores; cache-hit returns without network (Req 3.1, 3.2) — the cache-hit test monkeypatches the HTTP function to raise, proving no network call.
- Cache directory is git-ignored (Req 3.3) — assert the path is covered by a `.gitignore` pattern.
- Concurrency: N threads requesting the same missing corpus against an instrumented fetch invoke the network at most once and return identical content (Req 4.1-4.3).
- Hard-fail: forcing an HTTP failure with an empty cache raises `CorpusError` whose message contains the corpus name and SHA, and is an error rather than a skip (Req 5.1-5.4).

**Smoke checks:**

- `import hypothesis` succeeds in each matrix cell (Req 1.2); pinned SHA constants are well-formed 40-hex strings (Req 2.1, 2.2).

**Property test configuration:**

- Minimum **100 iterations** per property test (`max_examples=100` in the `ci` profile).
- Each property test references its design property via the tag:
  **Feature: property-based-tests, Property {number}: {property_text}**
- Corpus properties draw with `data.draw(st.sampled_from(...))` over a session-loaded (non-empty) list, so the fixed corpus is fetched and parsed once and shared across xdist workers through the on-disk cache (Req 10.3).
- `print_blob=True` and Hypothesis's default reporting surface counterexamples in pytest output (Req 10.4).

**Matrix compatibility.** All modules live under `tests/` (Req 10.1) and use only stdlib + `hypothesis` + the package under test, so they run identically on Python 3.11 and 3.12 (Req 10.2).
